### ✅ M1 [concurrency] `log-sdk/src/main/java/com/hj/log/sdk/fallback/ReplayWorker.java:65-70` + `FallbackReader.java:44-60`（已修）

replay vs write 同小时文件竞争——原方案释放锁后 send 期间 FallbackWriter 可能追加新事件，safeDelete 会连同这些未 replay 的新事件一起删除。

**修复**：引入 `rename-before-send`——ReplayWorker.claimForReplay 用 `Files.move(..., ATOMIC_MOVE)` 把 `*.ndjson` 原子改名为 `*.ndjson.replay` 独占该批；FallbackWriter 下一次 `write()` 以 CREATE 模式打开原文件名，落入新文件；两者目标分离。FallbackReader.listPendingFiles 同时识别 `.ndjson` 与 `.ndjson.replay`，跨 JVM 重启可拾起孤儿。

### ✅ M2 [error-handling] `log-sdk/src/main/java/com/hj/log/sdk/fallback/FallbackReader.java:73-77`（已修）

readAll 的 IOException 原返 `List.of()` → ReplayWorker 空列表分支 safeDelete 直接删除 IO 故障文件，数据永久丢失。

**修复**：IOException 改返 `null`，与"锁未取得"语义对齐；ReplayWorker null 分支跳过不删除，下一轮重试。

### ✅ M3 [observability] `log-sdk/src/main/java/com/hj/log/sdk/transport/HttpTransport.java:88-96`（已修）

IOException / InterruptedException 静默返 TRANSIENT_ERROR，生产网络故障无法定位。

**修复**：补 WARN 日志（仅异常类名+message，不打堆栈防日志洪水）；InterruptedException 也补独立日志行。
